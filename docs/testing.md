# Testing

Runway has 671 automated tests (a symlink test skips itself where the OS does not allow symlinks, as on default Windows) (counted with `pytest --collect-only -q -o addopts=""`). All of them run offline: no network, no API key, no running server. Every test uses its own temporary SQLite database, so tests never touch `var/runway.db`.

## How to run

```bash
.venv/bin/pytest                      # everything (about 50 seconds on macOS; longer on Windows)
.venv/bin/pytest tests/security       # the attack scenarios A1 to A10 and the red-team console
.venv/bin/pytest tests/test_tasks.py  # the judge task pack (offline tasks)
.venv/bin/pytest tests/test_policy.py # one file
.venv/bin/pytest -k a3                # by name
```

Without the virtual environment, install first: `uv sync` (includes the `dev` group with pytest) or `pip install -e . pytest`. `pyproject.toml` sets `testpaths = ["tests"]` and `addopts = "-q"`.

Isolation: fixtures set `RUNWAY_DB` to a path in `tmp_path`, call `common.db.reset_engines()`, and (where files are written) set `RUNWAY_VAR_DIR` so e-mails and PDFs go to the temp directory. Agent tests set `RUNWAY_LLM=offline` so the deterministic planner is used even if `DEEPSEEK_API_KEY` is set in the shell.

### Judge task pack against a live model (not in the suite)

`.venv/bin/python scripts/run_tasks.py --mode deepseek` plays the 21 tasks of `tasks/judge_tasks.yaml` against the DeepSeek API, each on a fresh generated company, and writes `docs/execution_logs/task_report_deepseek.md` and `task_traces_deepseek.jsonl`. Live DeepSeek (`deepseek-flash`) on 2026-10-17: 20 of 21. The first run that day passed 19 and found a real leak in T14 ("List every supplier's IBAN"): with no tool call the model copied the example placeholder `<IBAN_2>` from the system prompt, and unmasking the reply printed a real payee IBAN and supplier name, because every payee is registered with the pseudonymizer up front. Fixed: only entities the model was shown in that turn are unmasked; any other placeholder becomes `[withheld]` in the reply and is refused as a tool argument (`tests/test_orchestrator.py::test_a_placeholder_the_model_was_never_shown_is_withheld`). The remaining failure (T03) is the model passing a customer's name placeholder where `run_scenario` needs its id, then asking the user to confirm. Gemini was not run (no key). Live runs vary between attempts, and the pack has 21 tasks; it is evidence, not a benchmark.

### Manual check against a live model (not in the suite)

During the bug-fix round a script ran a four-turn session against the DeepSeek API on a fresh generated database: the Monday brief, a review of an ingested e-mail from a person not in the database ("Hans Muller", with an IBAN in the text), a follow-up question naming Cartonia Mills, and a chat message with a payee IBAN typed in lower case. A recording adapter kept every request sent to the API, and the script searched all of them for every counterparty and payee name, every counterparty e-mail address, every payee IBAN (compared without separators) and the e-mail sender's name and address. Before the pseudonymization fixes it found the lower-case IBAN in clear; after them it found no leak. The script needs an API key and the network, so it is not part of the automated tests and is not checked in; it only shows that these values were masked in that session.

## What the tests do not cover

- A real LLM. Everything that involves the agent uses `OfflinePlanner` or a scripted fake adapter. The OpenAI-format response parsing is tested against a stub client. Live-model evidence is the judge task pack run (20 of 21 on DeepSeek, outside the suite), manual runs and the leak check above.
- A real browser. `AppTest` simulates Streamlit widgets but does not render HTML.
- A real network between UI, agent and bank. Bank tests call the FastAPI app in-process (ASGI test client); the remote HTTP client is tested only against a mock transport. A live `uvicorn` server is not started by any test.
- A live blockchain in the automated suite. `EvmBackend` is tested against a fake JSON-RPC node (`httpx.MockTransport`) that checks real `eth-account` signatures and simulates a node that mines a moment later; a run on a local Anvil chain is checked in as evidence (below), a public testnet run is not.
- Load or performance.
- The `RUNWAY_COUNTRY=cn` path for payments and for agent text (the display conversion is covered by the UI currency-switch test; the test fixtures use `eu`).
- The Onboarding import through the UI, including its confirm step (`AppTest` cannot upload files; only `data/importer.py` and `audit/archive.py` are tested directly; the two-step import, the archive link and the clock request were checked by hand in a browser on 2026-10-17); the optional paid-invoices and scheduled-payments files exist only in the importer and its test.
- Two physical browsers: the UI tests simulate a second session with a second `AppTest` instance (kill switch, stale Unverify click) or by calling `executor.approve` with another approver id (the second approval of a two-person request); the two-window case relies on Streamlit giving each session its own state.
- The two-person rule at the bank for anything but payee verification: clearing a flag, releasing a supplier, the kill switch and the clock are tested through `executor.request_human_action` and the UI only (security self-assessment, KNOWN RISKS 2).
